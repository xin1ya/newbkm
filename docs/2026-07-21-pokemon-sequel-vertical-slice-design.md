# 口袋妖怪续作 · 翠澜群岛 · 垂直切片设计文档

**日期**：2026-07-21
**状态**：设计已批准，待实现计划
**范围**：垂直切片（MVP）—— 1 镇 + 1 路线 + 1 道馆，验证核心循环

---

## 1. 概述

制作一款口袋妖怪续作，新区域「翠澜群岛」+ 现有宝可梦。采用 Web 平台（Phaser.js），先交付一个能跑通"探索→遇敌→战斗→捕捉→道馆"核心循环的垂直切片，再逐步扩展。战斗引擎按正统作品全保真，内容范围精简。

### 1.1 核心决策

| 维度 | 决策 |
|------|------|
| 技术栈 | Vite + Phaser 3 + TypeScript |
| MVP 形态 | 垂直切片（1 镇 + 1 路线 + 1 道馆） |
| 续作定位 | 新区域 + 现有宝可梦（用 PokeAPI 数据） |
| 数据来源 | PokeAPI（数值 + 美术），用户指定网站作备选 |
| 美术方向 | 现代插画风（战斗用官方插画，地图简洁现代风） |
| 实现策略 | 引擎深、内容窄：战斗全保真，切片内容精简 |
| 战斗界面 | 现代居中布局（圆角半透明面板、细 HP 条） |

## 2. 创意设定

### 2.1 区域
**翠澜群岛（Verdant Isles）**：海岸群岛区域，小岛 + 沿海森林。主题适合水/草/飞/电/虫多属性搭配。

### 2.2 御三家（续作 remix，跨世代各选一人气角色）
- 🌿 草系：木木枭（Rowlet #722，草/飞）
- 🔥 火系：火球鼠（Cyndaquil #155，火）
- 💧 水系：水跃鱼（Mudkip #258，水）

### 2.3 区域图鉴（约 13 只）
御三家 + 波波、小拉达、绿毛虫→巴大蝶、皮卡丘、走路草、玛瑙水母、海星星、大钳蟹、蚊香蝌蚪、鲤鱼王→暴鲤龙。
覆盖属性：草/火/水/电/飞/虫/毒/普，足够支撑路线遇敌和道馆队伍。

### 2.4 地图（线性）
起始镇（博士实验室 + 宝可梦中心 + PC）→ 1 号路线（草丛遇敌）→ 翠澜镇（水系道馆）。

### 2.5 道馆
水系道馆。馆主队伍：海星星 + 大钳蟹 + 暴鲤龙。通关给徽章。

### 2.6 剧情钩子
切片阶段极简：玩家从木兰博士处领初始宝可梦，穿越 1 号路线去翠澜镇挑战道馆。留一句"数年前群岛的异变"作为续作伏笔，不展开。

## 3. 架构

### 3.1 技术栈
- **Vite**：开发服务器 + 打包
- **Phaser 3**：2D 游戏引擎
- **TypeScript**：类型安全
- **Vitest**：单元/集成测试

### 3.2 Phaser 场景结构
```
BootScene          # 加载最小素材
  → PreloadScene   # 进度条，加载全部素材
    → TitleScene   # 标题 / 新游戏 / 继续
      → OverworldScene   # 俯视地图探索、移动、草丛遇敌、对话、进建筑/道馆
        → BattleScene    # 1v1 回合制战斗（叠加在地图上）
        → PartyScene     # 队伍查看/管理（叠加层）
        → MenuScene      # 主菜单（叠加层）
```

### 3.3 项目结构
```
pokemon-sequel/
├── public/
│   └── assets/          # 精灵图、官方插画、音频、地图 JSON
├── src/
│   ├── scenes/          # 各 Phaser 场景（一文件一场景）
│   ├── systems/         # 战斗引擎、遇敌、队伍、存档
│   ├── data/            # 本地 JSON 数据（宝可梦/招式/属性）
│   ├── config/          # 区域地图、遇敌表、训练家、道馆
│   ├── ui/              # UI 组件（对话框、菜单、HP 条）
│   ├── types/           # TS 类型
│   └── main.ts          # 游戏入口
├── scripts/
│   └── fetch-data.ts    # 一次性 PokeAPI 抓取脚本 → src/data/*.json
├── tests/               # 单元 + 集成测试
├── index.html
├── package.json
├── tsconfig.json
└── vite.config.ts
```

### 3.4 数据层
PokeAPI 数据由 `scripts/fetch-data.ts` **一次性抓取**，归一化后存为 `src/data/*.json`。游戏运行时只读本地文件，**零网络请求**，绕开 PokeAPI ~4s 延迟。图片下载到 `public/assets/`。

### 3.5 存档
localStorage（key: save slot）。存队伍、背包、剧情标志、玩家位置、图鉴已见/已捕。

## 4. 核心系统

### 4.1 战斗系统（全保真）
- **模式**：1v1 单打，回合制
- **回合顺序**：先制度段 → 速度（麻痹×0.25 等）
- **完整伤害公式**（Gen5+）：
  `((2*等级/5+2)*威力*攻击/防御)/50 + 2`
  叠加：STAB(1.5) / 属性克制表 / 暴击(1.5，忽略负能力阶) / 烧伤(物理半减) / 天气 / 随机(0.85~1.00) / 携带物 / 特性
- **能力阶**：-6~+6，攻防特攻特防按 `(2+阶)/(2-阶)`；命中闪避同理
- **特性**：每只按 PokeAPI 取特性；实现一组核心特性（约 15 个：威吓、大力士、蓄水、避雷针、静电、叶绿素、悠游自如、雨盘、茂盛/猛火/激流、结实、蜕皮等），未实现的按 no-op
- **携带物**：实现一组核心（约 10 个：专爱头带/围巾、生命宝珠、剩饭、属性强化道具等），其余 no-op
- **性格**：25 种，+10%/-10% 两项
- **个体值(0-31) + 努力值(0-252, 总≤510)**：玩家宝可梦击败获努力值；野生/馆主固定
- **异常/状态**：烧伤/麻痹/中毒/剧毒/睡眠/冰冻/混乱/魅惑/畏缩
- **天气**：雨/晴/沙/冰雹（切片用雨水系道馆氛围）
- **招式**：威力/属性/命中/PP/分类/先制度/对象/次级效果（能力阶变化、附加状态、畏缩）；按 PokeAPI 升级表学招，激活 4 个
- **切换**：濒死免费换；主动换算消耗回合
- **AI**：馆主按克制+威力+规避免疫选招；野生随机
- **捕获**：完整摇晃公式 `(3*最大HP-2*当前HP)*捕获率*球加成/(3*最大HP) * 状态加成`
- **经验/升级/进化**：经验按比例；进化按等级（切片只做等级进化）

### 4.2 探索 / 遇敌
- 俯视瓦片地图，玩家四向移动，碰撞检测
- 草丛：每步概率触发遇敌，物种/等级按路线遇敌表
- NPC 对话框，进入建筑/道馆的场景切换

### 4.3 捕捉
野生战斗 → 背包 → 精灵球 → 捕获率公式 + 摇晃检查。捕获后入队伍，满则入盒子（盒子=列表存储）。初始宝可梦从博士处三选一。

### 4.4 队伍
最多 6 只，多余入盒；查看属性/招式、换序、用道具；中心治疗。

### 4.5 道馆
馆主=脚本化训练家战斗（3 只、固定等级、AI 尽量选克制招式）。胜利 → 徽章 + 切片通关字幕。

### 4.6 战斗界面（现代居中布局）
- 敌方 HP：顶部居中细条（圆角半透明白底）
- 敌方插画：中右，官方插画
- 玩家插画：中左，官方插画（水平翻转朝右）
- 玩家 HP：中右细条（圆角半透明白底，含等级/当前-最大 HP）
- 菜单：右下圆角半透明深色面板（战斗/背包/队伍/逃跑 → 招式列表）
- 背景：上天下地渐变（场景化）

## 5. 数据管线

### 5.1 一次性抓取脚本 `scripts/fetch-data.ts`
**输入**：区域图鉴 13 个 species id + 御三家 + 招式/属性表
**输出**：
- `data/species.json` — id、中英文名、属性、种族值(6项)、特性列表、捕获率、基础经验、进化链、升级招式表、插画/sprite URL
- `data/moves.json` — 招式：威力/属性/命中/PP/分类/先制度/对象/次级效果
- `data/types.json` — 18 属性克制表
- `data/abilities.json` — 特性 id/名/描述（仅抓取，实现的核心特性在代码里映射）
- `data/items.json` — 携带物（同上）
- `data/natures.json` — 25 性格

**图片下载**：每只宝可梦的 official-artwork + front sprite + shiny，存到 `public/assets/pokemon/{id}/`

**限速**：每请求间 200ms，带重试
**幂等**：已存在文件跳过，支持断点续抓
**校验**：抓取后校验字段完整性，缺失字段记日志

### 5.2 运行时
游戏只读 `src/data/*.json` 和 `public/assets/`，零网络请求。

### 5.3 更新
加新宝可梦时，改脚本输入列表重跑，增量下载。

## 6. 范围边界

### 6.1 切片内做
- 1 镇（起始镇）+ 1 路线（1 号路线）+ 翠澜镇水系道馆
- 13 只区域图鉴（御三家 + 10 野生/进化线）
- 全保真 1v1 战斗引擎（属性/特性/携带物/性格/个体值/努力值/异常/天气/能力阶/完整伤害公式）
- 捕捉、队伍(6+盒子)、升级、按等级进化、学招
- 道馆馆主战 + 徽章 + 切片通关字幕
- 存档（localStorage）、宝可梦中心治疗
- 现代居中战斗 UI、对话、菜单
- 简单伏笔一句（不展开）

### 6.2 切片不做（留给后续迭代）
- 多镇多路线/完整区域地图、全部 1000+ 宝可梦
- 双打/皇家等非 1v1 战斗
- 通信交换、GTS、对战联网
- 完整剧情/多 NPC 支线/反派组织
- 非等级进化（石头/交换/友好度等）、mega/Z/极巨/太晶
- 昼夜系统、钓鱼、秘传技、自行车等地图机制
- 音效配乐（切片用占位或免版权素材，非核心）
- 多周目、二周目内容
- 金钱/商店经济（切片中心免费治疗，球道具固定给）

### 6.3 测试策略
- **单元测试**（Vitest）：战斗引擎核心 —— 伤害公式、属性克制、能力阶、特性、异常状态，用已知数值用例校验
- **集成测试**：关键流程 —— 遇敌→战斗→捕获→入队、升级学招进化
- **手动 QA**：走通 起始镇 → 1 号路 → 道馆 全流程

## 7. 风险与取舍

| 风险 | 应对 |
|------|------|
| PokeAPI 单请求 ~4s | 一次性抓取 + 本地缓存，运行时零网络 |
| 战斗引擎复杂度高 | 核心机制写单元测试，未实现特性/道具 no-op 兜底 |
| 美术资源一致性 | 全部来自 PokeAPI 同源，风格统一 |
| 切片范围蔓延 | 明确范围边界（第 6 节），新需求入后续迭代 |
| Tiled 瓦片地图制作成本 | 小地图可手搓 JSON，避免依赖外部编辑器 |
