## 1. 概述

### 1.1 什么是「半开放世界」

本作采用**岛屿级开放、群岛级线性**的结构：

- **岛内开放**：每座岛是一块无缝连续的 3D 地图。城镇、野外、湖泊、山地之间没有加载切换，玩家可以自由选择路径与探索顺序。
- **岛间有序**：岛屿之间由海域隔开。进入下一座岛需要主线条件（徽章数 + 骑乘能力）。整体剧情顺序仍然是 岛1 → 岛2 → 岛3 → 岛4 → 岛5。
- **岛内软引导**：同一座岛上的多个道馆**不强制顺序**。道馆队伍等级按「本岛已获徽章数」动态调整（见 §5.4），保证任意顺序都有合理难度。
- **室内独立**：建筑内部、道馆、洞窟、遗迹是独立场景，通过门/入口进入。这样可以控制性能，也便于设计谜题。

这种结构的好处：保留宝可梦系列清晰的成长节奏与剧情顺序，同时给每座岛足够的探索自由；地图规模可控，Web 端也能流畅运行。

### 1.2 设计支柱

1. **看得见的生态**：野生宝可梦在世界中游荡、睡觉、成群活动，昼夜与天气影响出现种类。
2. **岛屿即主题**：每座岛有独立的地貌、配色、音乐与生态（见 §3）。
3. **能力解锁探索**：骑乘宝可梦逐步解锁冲浪、碎岩、攀爬、登瀑、潜水、飞行，旧区域会因此出现新路线（类银河城式回访）。
4. **异变可视化**：主线「异变」在世界中有可见表现（异变结晶、扭曲地形、异色气候），推进主线会改变世界面貌。

## 2. 技术架构

### 2.1 技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| 渲染 | Three.js r16x（WebGL2） | 已在真新镇 demo 中验证：地形、水面着色器、实例化植被、昼夜、阴影 |
| 语言/构建 | TypeScript + Vite | 新建工程；Vite 负责开发服务器与打包 |
| 物理/碰撞 | 自研轻量碰撞（高度图 + 胶囊体 + 静态 BVH） | 用 `three-mesh-bvh` 做静态网格射线/胶囊查询，不引入完整物理引擎 |
| 资源格式 | glTF 2.0（.glb）+ Draco/Meshopt 压缩 + KTX2 纹理 | 模型与动画统一格式 |
| UI | DOM/CSS 叠加层（HUD、菜单、对话、战斗 UI） | demo 中的对话/菜单系统可直接移植 |
| 音频 | WebAudio（Howler.js 可选） | BGM 按区域淡入淡出，环境音分层 |
| 存档 | IndexedDB（localStorage 兜底） | 经 `Platform` 层读写，结构见 §11 |
| 测试 | Vitest（逻辑单测）+ Playwright（冒烟截图） | |
| 桌面打包 | Tauri 2（后期） | 见 §2.3 |

### 2.2 模块划分

```
src/
  core/          Game 主循环、时间系统、输入、事件总线、存档
  world/
    island/      IslandConfig 加载、分块流式加载、LOD
    terrain/     高度图、地表材质通道（splat）、水体
    foliage/     实例化植被、风摆着色器、草丛交互
    props/       建筑/岩石/路灯等摆放物、碰撞体生成
    sky/         天空、昼夜、天气（晴/雨/雾/雪/雷暴/异变）
    spawns/      野生宝可梦刷新、AI 行为
  scenes/
    OverworldScene   岛屿开放世界
    InteriorScene    室内/道馆/洞窟/遗迹（按需加载）
    BattleScene      3D 战斗
    UI 叠加：Dialog / Menu / Party / Bag / Quest / Map / Pokedex
  actors/        玩家、NPC、跟随宝可梦、骑乘
  systems/       quests.ts、battle 逻辑、捕获、经验、道馆、渡船
  config/        islands/ zones/ npcs/ quests/ species/ encounters/
```

**分层原则**：战斗计算、属性相克、经验、捕获、任务推导等**纯逻辑**放在 `src/systems/`，不依赖 Three.js 与 DOM，可在 Node 中单测；渲染与输入放在 `world/`、`scenes/`、`actors/`、`ui/`。

### 2.3 Tauri 桌面版预留

现在只做 Web，但以下约束从第一天起遵守，保证以后能直接用 Tauri 2 打包：

- **平台抽象层** `src/platform/`：存档、文件读取、窗口/全屏、退出游戏都经过接口 `Platform`，Web 实现用 IndexedDB / fetch，以后新增 Tauri 实现（`@tauri-apps/api` 的 fs、window）。业务代码禁止直接调用 `localStorage`、`indexedDB`、`window.close`。
- **资源路径**全部使用相对路径 + Vite 的 `import.meta.env.BASE_URL`，不写死域名，不依赖服务器端路由。
- **不依赖在线服务**：游戏运行时不请求任何外部 API（数据抓取只在构建期脚本中进行）。
- **输入**：键鼠 + 手柄（Gamepad API），不依赖浏览器特有快捷键（如 F11 全屏交给 `Platform`）。
- 构建产物是纯静态目录（`dist/`），Tauri 直接指向它即可。

## 3. 群岛世界结构

### 3.1 岛屿总览

| 岛 | 名称 | 可探索面积 | 城镇 | 道馆 | 地貌主题 | 解锁条件 |
|----|------|-----------|------|------|---------|---------|
| 1 | 萌芽群岛 | ~1.0 km² | 3 | 1 | 温带草原、海岸、浅海、雾林 | 开局 |
| 2 | 碧潮群岛 | ~1.8 km² | 4 | 3 | 古树森林、矿山峡谷、活火山、温泉 | 徽章×1 + 冲浪 |
| 3 | 雷鸣群岛 | ~2.0 km² | 4 | 4 | 雷暴高原、晨光平原、冰川雪原、悬崖云顶 | 徽章×4 + 碎岩 |
| 4 | 琉璃群岛 | ~1.6 km² | 3 + 联盟 | 3 | 玻璃海岸、幽灵沼泽、海蚀石林、冠军之路 | 徽章×8 + 攀爬 |

### 3.2 各岛布局

每座岛的描述包括：城镇（据点）、野外区域（原「路线」在 3D 中变成有主题的区域）、兴趣点、岛内封锁与回访内容。

#### 岛 1 · 萌芽群岛（起始·水）

| 城镇 | 类型 | 道馆 | 3D 场景要点 |
|------|------|------|-------------|
| 萌芽镇 | 起始镇 | 无 | 海边小镇，玩家家、木兰博士研究所（室内）、码头 |
| 翠澜镇 | 城镇 | 水系·道馆1（沧澜） | 湖上水乡，木栈道连接高脚屋，道馆建在湖心 |
| 港湾市 | 港口商业镇 | 无 | 群岛渡船枢纽，市场、钓鱼码头、灯塔 |

- **野外区域**：
  - 萌芽草原（原 1 号路）：新手区，低等级遇敌，教学引导。
  - 翠澜湖畔：浅水区，水系宝可梦多。
  - 港湾海崖（原「新路线」）：海岸悬崖步道，飞行系宝可梦多。
- **支线地点**：幻影之森（岛西北雾林，索罗亚事件）。森林中雾气会随机变换路径，需要跟着索罗亚的脚印走。
- **封锁**：开局时翠澜湖心道馆需要主线剧情解锁；港湾市码头出海需要冲浪（道馆1 奖励）。
- **回访**：取得碎岩后可进入萌芽草原海崖下的隐藏洞穴。

#### 岛 2 · 碧潮群岛（草·岩·火 + 异变遗迹）

| 城镇 | 道馆 | 3D 场景要点 |
|------|------|-------------|
| 碧潮镇 | 草系·道馆2（叶岚） | 巨树根系上建城，树屋与吊桥 |
| 矿石镇 🆕 | 岩石系·道馆3（岩磊） | 峡谷内的矿业小镇，矿车轨道、矿洞入口 |
| 火山镇 | 火系·道馆4（炎棘） | 火山山腰，熔岩河、黑曜石建筑 |
| 温泉乡 🆕 | 无 | 山谷温泉，培育屋，温泉可恢复队伍 |

- **岛内自由顺序**：三座道馆分别位于岛的西（森林）、中（峡谷）、东（火山），玩家可以任意顺序挑战。
- **主线地点**：异变遗迹，位于岛中央高原。入口平台在 3 枚本岛徽章前会被异变结界封住（可见的紫色屏障）。深处是原初守护者 BOSS，击败后获得**碎岩骑乘**。
- **支线地点**：
  - 翠澜森林（居合斩区域在 3D 中改为「被藤蔓封住的小径」，用草系骑乘或割草道具打开）
  - 火山洞窟（需要闪光：洞内全黑，用电/火系跟随宝可梦照明）
- **出海**：温泉乡码头 → 碧潮—雷鸣海域 → 雷鸣镇。

| 城镇 | 道馆 | 3D 场景要点 |
|------|------|-------------|

### 3.3 海域与跨岛

2D 版的 4 张「水路地图」在 3D 中改为**开放海域**：

| 海域 | 连接 | 形态 | 遇敌 |
|------|------|------|------|
| 萌芽—碧潮海域 | 港湾市 ↔ 碧潮镇 | 平静浅海，珊瑚礁小岛 | 低等级海系（玛瑙水母/海星星/鲤鱼王） |
| 碧潮—雷鸣海域 | 温泉乡 ↔ 雷鸣镇 | 有洋流与漩涡 | 中等级（大钳蟹/蚊香君/暴鲤龙） |
| 雷鸣—琉璃海域 | 云雀镇 ↔ 幻影镇 | 海雾、礁石迷宫 | 高等级（白海狮/宝石海星/暴鲤龙） |
| 秘境航线 | 琉璃镇 ↔ 秘境岛 | 仅渡船，过场动画 | 无 |

- **航线走廊**：每片海域是一条宽约 300–500 m 的走廊，而不是整片无边大海。走廊边缘用巨浪/暗礁/海雾自然封边。走廊内有小岛、沉船、浮标等兴趣点。
- **冲浪**：面朝水面按交互键骑上水系宝可梦。海面有可见的野生宝可梦（跃出水面的鲤鱼王、成群的海星星），以及水下暗影触发的暗雷遇敌。
- **渡船快线**：完成 `main-harbor-ferry` 后，已到访岛屿的码头之间可乘船快速往返（黑屏 + 船上过场）。
- **飞行（后期）**：取得飞行骑乘（道馆8 奖励）后，可在已到访城镇的「宝可梦中心」之间快速旅行，也可以在岛内低空滑翔。

### 3.4 能力解锁：骑乘宝可梦取代 HM

2D 版的 HM 道具改为**骑乘能力**：学会后不占招式栏，用专用按键呼出骑乘宝可梦。原任务中 HM 奖励一一对应到骑乘能力，任务 ID 与 flag 保持不变。

| 原 HM / flag | 3D 骑乘能力 | 获得时机 | 世界作用 |
|--------------|------------|---------|---------|
| HM03 冲浪 `hm03-surf` | 水上骑乘 | 道馆1 | 在水面移动、出海 |

## 4. 地形与场景构建

### 4.1 岛屿数据格式

`maps.ts` 的瓦片字符地图被以下配置取代：

```typescript
// src/config/islands/types.ts
interface IslandConfig {
  id: 'sprout' | 'tide' | 'thunder' | 'glaze' | 'secret';
  name: string;                 // 萌芽群岛
  size: [number, number];       // 世界尺寸（米）
  heightmap: string;            // 16 位 PNG 高度图路径
  splatmaps: string[];          // 地表材质权重图（每张 RGBA = 4 种材质）
  seaLevel: number;
  zones: ZoneConfig[];          // 野外区域 / 城镇范围
  props: string;                // 摆放物数据文件（glb 实例列表）
  pois: PoiConfig[];            // 兴趣点：门、码头、道馆、支线地点入口
  blockers: BlockerConfig[];    // 能力封锁点
  spawnPoint: [number, number, number];
}

interface ZoneConfig {
  id: string;                   // 'sprout-meadow'（原 route-1）
  name: string;                 // 萌芽草原
  kind: 'town' | 'wild' | 'sea' | 'dungeon-entrance';
  polygon: [number, number][];  // 区域边界（XZ 平面）
  bgm: string;
  encounterTable?: string;      // 引用 encounters/*.json
  levelRange?: [number, number];
  weather?: WeatherRule[];
  legacyMapId?: string;         // 对应 2D 设计文档中的地图 ID，便于对照原设计
}

interface BlockerConfig {
  id: string;
  type: 'rock-smash' | 'strength' | 'vines' | 'climb' | 'waterfall' | 'dive' | 'dark' | 'story';
  requiresFlag: string;         // 沿用原 flag 名
  position: [number, number, number];
  hint: string;
}
```

**与 2D 设计的对照**：2D 文档中的 ~65 张地图（30 张既有 + 35 张新增）→ 每张对应一个 `ZoneConfig`（带 `legacyMapId`）或一个室内场景，便于按原设计核对内容。

- 2D 设计中的 `WALKABLE` / `KNOWN_CHARS` / `validateMaps()` 不再实现，改为 §12 的岛屿校验。

### 4.3 分块流式加载与 LOD

- 每座岛切成 **128 m × 128 m** 的块（chunk）。
- 玩家周围 **3×3 块**全精度加载，**5×5 块**以内加载低精度地形与树木替身（impostor），更远处只显示整岛低模剪影 + 雾。
- 植被使用 `InstancedMesh`，按块剔除；草丛只在 60 m 内渲染，并做距离淡出。
- 城镇建筑有 2 级 LOD；室内场景按需加载，进门时淡入淡出（<1 s）。

### 4.4 世界制作流程

1. **高度图与材质图**：在 Blender / World Machine / Gaea 中制作高度图，导出 16 位 PNG 与材质权重图。
2. **摆放物**：在 Blender 中摆放建筑与地标，导出实例列表（位置/旋转/缩放 + 资源 ID）；大面积植被由程序根据材质权重与区域规则自动散布。
3. **游戏内编辑器（开发模式）**：按 F9 打开，可拖放 NPC、POI、封锁点、刷新点，保存为 JSON。
4. 每座岛先做**灰盒**（仅高度图 + 色块）验证路线与节奏，再进入美术阶段。

### 4.5 天空、昼夜与天气

- 参考真新镇 demo 的昼夜循环（天空渐变、日月、星空、夜间窗灯/路灯）。游戏内 1 天 = 现实 24 分钟。
- **天气**按区域规则随机：晴、雨、雾、雪、雷暴、沙尘，以及剧情用的**异变天气**（紫色天空、漂浮碎石）。
- 天气影响：遇敌表（如雨天水系增多）、战斗天气效果、NPC 对话、部分谜题（雷暴时避雷塔通电）。

### 5.2 刷新与 AI

- 每个区域有 `encounterTable`：种类、权重、等级范围、时段（昼/夜/全天）、天气条件、刷新形态（单只/群体/稀有）。
- 刷新半径：玩家周围 25–70 m 内维持 N 只（按区域配置，通常 6–12 只），离开 90 m 外回收。
- **行为性格**（按种族配置）：
  - 胆小：看到玩家会逃跑（绿毛虫、波波）
  - 好奇：靠近玩家观察
  - 好斗：发现玩家后冲过来（小拉达、大钳蟹）
  - 睡觉：夜间躺在固定位置，背后接近可获得先手
- **稀有与头目**：每个区域有低概率的**异色**与体型更大的**头目个体**（等级 +5，头顶有标记）。

### 5.3 进入战斗

- 接触时一方先手：玩家从背后接近 → 玩家先手；被宝可梦冲撞 → 对方先手；正面 → 按速度判定。
- 进入战斗**不切换地图**：以遇敌点为中心展开战斗场，周围地貌保留，远处其他宝可梦暂停。

### 5.4 等级曲线（适配岛内自由顺序）

- 野外等级按区域固定，形成自然的「推荐路线」。
- 本岛道馆馆主的队伍按「**本岛已获徽章数**」取三档等级，例如岛 2：第 1 座挑战的道馆 Lv 18–20，第 2 座 Lv 23–25，第 3 座 Lv 28–30。道馆的主题与招式不变。

### 8.1 版权与授权（已决议：内部学习项目）

宝可梦及其形象、名称属于任天堂 / Game Freak / The Pokémon Company。本项目定位为**内部学习项目**，因此：

### 8.2 宝可梦 3D 模型：全部手工制作

~300 种全部手工建模、绑骨、制作动画。按重要程度分为两档**精度**（都是手工）：

| 档位 | 数量 | 范围 | 规格 |
|------|------|------|------|
| S | ~40 | 御三家全进化线（木木枭/火球鼠/水跃鱼）、13 位馆主王牌、神兽、剧情宝可梦 | ≤ 15k 三角面，1024 贴图，完整动画 10 个（待机×2/行走/奔跑/物理攻击/特殊攻击/受击/倒下/睡觉/骑乘） |
| A | ~260 | 其余全部 | ≤ 8k 三角面，512 贴图，标准动画 8 个（待机/行走/奔跑/物理攻击/特殊攻击/受击/倒下/睡觉） |

- **统一规范**：朝向 +Z、脚底 y=0、1 单位 = 1 米、按图鉴身高缩放；骨骼命名统一（`root/hips/spine/head/...`），动画片段名统一，便于共用同一套动画状态机。
- **材质**：统一使用 Toon 材质（见 §8.4）；贴图以平涂色块为主，只画少量阴影与高光，减少与 Toon 着色冲突。
- **异色**：同模型换一张贴图或一组材质色。
- **产能与排期**：按单人每种 A 档约 2–3 天、S 档约 5–7 天估算，全量约 800–1000 人日。**模型制作是本项目的关键路径**，因此：
  1. 按岛屿推进：每个里程碑只制作该岛出现的宝可梦（见 §13）；
  2. 开发期允许使用**灰模占位**（统一胶囊体 + 名字标签），代码不等待美术；
  3. 资源清单与完成状态在主控文档中跟踪。

### 8.4 美术风格：卡通渲染（Toon 着色 + 描边）

- **着色**：自定义 Toon 材质（基于 `MeshToonMaterial` 或 `onBeforeCompile` 扩展）：
  - 3 阶明暗色带（亮 / 中 / 暗），色带贴图按岛屿可调；
  - 边缘光（rim light），让角色从背景中跳出来；
  - 高光为硬边小色块；支持接收阴影（阴影也按色带量化）。
- **描边**：
  - 角色与宝可梦：**反向外壳法**（inverted hull），按距离调整描边粗细，颜色取材质主色的暗色；
  - 场景：**后处理边缘检测**（深度 + 法线），线条统一深色、较细；
  - 草、花、粒子不描边，避免画面过脏。
- **后处理**：轻微 bloom（夜灯、异变结晶、招式特效）、色调映射、可选描边强度与色彩饱和度调节。
- **配色**：每座岛一套主色板（萌芽：嫩绿/天蓝；碧潮：深绿/赭石/熔岩橙；雷鸣：紫灰/金黄/冰蓝；琉璃：玻璃青/暗紫；秘境：梦幻粉紫/冷白）。
- **CC0 素材的统一**：外部植被、建筑素材导入后统一替换为 Toon 材质并重新配色，保证风格一致。
- **性能**：描边后处理约占 1–2 ms/帧；低画质档位关闭场景描边，只保留角色描边。

### 8.5 NPC 表现（对应原 §4.5–4.6）

- NPC 使用 3D 人物模型，按身份区分服装与配色（护士、店员、渔民、老人、小孩、博士、13 位馆主）。
- **名字标签**：头顶世界空间标签，15 m 内显示，随距离淡出（原方案是「始终显示」，在 3D 中改为距离显示，避免画面杂乱）。
- **互动提示**：原「面朝相邻格检测」改为「玩家前方 2 m 扇形范围内最近的可交互物」。提示类型沿用原表：
  - 对话 / 进入 / 渡船：E
  - 钓鱼：F
  - 冲浪及其他骑乘：R（呼出骑乘轮盘）
  - 封锁点：显示所需能力图标

- **第三人称**：肩后跟随，镜头碰撞回收，室内自动拉近（demo 已实现基础版）。
- **第一人称**：用于观察生态与拍照，隐藏玩家模型，保留跟随宝可梦。
- **野外投球**：可以不进入战斗直接向可见宝可梦投球，对低等级、睡眠中或背对玩家的个体有加成（捕获率按原公式 × 情境系数）。

## 12. 测试策略

- **单元测试**：任务状态推导、`trigger` 检测、等级动态档位、遇敌表抽取、捕获情境系数。
- **岛屿校验**（取代 `validateMaps`）：
  - 每个区域多边形都在岛内且互不重叠；
  - 每个 POI 从出生点可达（导航网格连通性检查，考虑当前能力集合）；
  - 每个封锁点的 `requiresFlag` 都能在主线中取得，不存在死锁。
- **集成测试**：道馆 → 徽章 → 骑乘能力 → 封锁点解除；冲浪横渡海域；渡船快线；室内进出。
- **性能测试**：Playwright 在固定路线跑图，记录帧时间与 draw call，超预算时报警。
- **手动 QA**：萌芽镇 → 全岛环游 → 联盟通关 → 秘境岛二周目全流程；岛 2、岛 3 的多种道馆顺序各测一遍。
